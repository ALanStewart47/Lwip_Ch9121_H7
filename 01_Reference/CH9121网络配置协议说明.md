# CH9121 广播发现与网络配置协议

## 1. 文档目的、范围与依据

本文说明串口测试工具对 CH9121 使用的 **UDP 广播发现与配置协议**，用于联调、抓包解读、第三方客户端实现和软件维护。这里的“端口1”是本工具 UI 中可编辑的串口透传端口；本文不定义业务串口协议。

本工具只支持以下九项配置：设备名、DHCP、IPv4 地址、子网掩码、网关、端口1波特率、数据位、停止位、校验位。以下内容不在本功能范围内，必须原样保留或不发送对应命令：端口2、网络工作模式、TCP 服务端口、扩展参数、时钟模式、串口控制命令和设备复位命令。

协议结论分为两类：

- **线上报文规则**：以当前 `01_Software/serial_test_tool/core/Ch9121ConfigProtocol.*` 与 `Ch9121ConfigClient.*` 为准；它们是本工具实际发送、接收和筛选报文的行为定义。
- **字段来源和实机证据**：交叉参考 WCH 网络配置示例工程、CH9121 EVT 文档及 2026-09-20 的实机“扫描 + 读取”样本。网络配置协议与串口控制命令对校验位编码的描述存在差异；本工具严格使用此处列出的 **UDP 配置** 编码，不能填入 Qt 枚举值或串口控制命令编码。

> 注意：本文描述的是项目实现的兼容边界，不声称覆盖所有 CH9121、CH9121A 或 CH9121T 固件版本。

## 2. 通信角色与端口

| 角色 | UDP 端口 | 行为 |
|---|---:|---|
| 配置客户端（电脑） | 60000 | 绑定 `0.0.0.0:60000` 接收设备应答；端口以独占方式绑定。 |
| CH9121 配置服务 | 50000 | 接收搜索、读取、写入报文，并从该源端口回包。 |
| CH9121 TCP 透传 | 默认 6600 | 仅是串口字节透传入口；不属于 UDP 配置协议，本文不修改其端口。 |

客户端要求用户明确选择一块 IPv4 网卡。发送时使用该网卡的 IPv4 地址、MAC 地址、接口索引和该 IPv4 地址对应的**定向广播地址**（通常是该子网的广播地址），而非对所有网卡盲目广播。接收端绑定 `AnyIPv4`，因此可以接收设备发往 `255.255.255.255:60000` 的广播应答；出站接口仍由接口索引限定。

因为本工具独占绑定 UDP 60000，运行官方配置工具或另一实例时可能发生端口冲突。应先关闭占用方，避免错收或漏收配置应答。

## 3. 公共报文格式

搜索、读取、写入及其应答都是**固定 285 字节**的 UDP 数据报，不追加 BCC、XOR、CRC 或长度外的尾部字节。收包时长度必须恰为 285 字节；多一字节、少一字节或标识不符的包均丢弃。

| 绝对偏移 | 长度 | 字段 | 编码/说明 |
|---:|---:|---|---|
| 0 | 16 | 协议标识 | ASCII `CH9121_CFG_FLAG` 加 `00`：`43 48 39 31 32 31 5F 43 46 47 5F 46 4C 41 47 00`。 |
| 16 | 1 | 命令 | 见第 4 节。 |
| 17 | 6 | 设备 MAC | 搜索请求全为 `00`；读取、写入请求填选中设备的报文头 MAC。 |
| 23 | 6 | 电脑 MAC | 所选网卡的有效单播 MAC。 |
| 29 | 1 | 有效数据长度 | 请求或应答的已定义数据长度；数据区本身始终保留 255 字节。 |
| 30 | 255 | 数据区 | 偏移 30～284；未定义字节也必须保留。 |

所有下文“数据区偏移”均相对偏移 30。若要换算成整包偏移，应加 30。例如端口1波特率的数据区偏移为 151，整包偏移为 181。

## 4. 命令与应答

| 操作 | 请求命令 | 成功应答 | 否定应答 | 长度字段 | 说明 |
|---|---:|---:|---:|---|---|
| 广播搜索 | `04` | `84` | `C0` | 请求 `00`；应答见下表 | 搜索时设备 MAC 全零。 |
| 读取完整配置（GET） | `02` | `82` | `C2` | 请求 `00`；应答 `CC` | 请求按目标 MAC 发出，数据区仍补齐 255 个零。 |
| 写入完整配置（SET） | `01` | `81` | `C1` | 请求 `CC`；成功应答 `00` | SET 只表示设备收到了写入请求，不能代替读回验证。 |

搜索成功应答（`84`）的数据区格式如下。`数据长度`等于 `4 + 名称区长度`；名称区含结尾 NUL，紧随其后的软件版本字节**不计入**数据长度。

| 数据区偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 4 | 当前 IPv4 地址，网络字节顺序。 |
| 4 | `数据长度 - 4` | 设备名，ASCII，通常以 `00` 结束。 |
| `4 + (数据长度 - 4)` | 1 | 软件版本。 |

客户端仅接受名称区长度为 1～21 且其后存在版本字节的搜索应答。扫描列表按**报文头设备 MAC**去重，同 MAC 的后到消息覆盖早到消息。

## 5. 广播发现流程

```text
电脑（选定 IPv4 网卡）                         CH9121
  bind 0.0.0.0:60000
  -- UDP 广播:50000，CMD=04，目标MAC=00..00 -->
  <-- UDP 应答:60000，CMD=84，设备MAC/IP/名称 --
  在 1500 ms 窗口内按报文头 MAC 去重
```

### 5.1 搜索请求组帧

```text
00..15   43 48 39 31 32 31 5F 43 46 47 5F 46 4C 41 47 00
16       04
17..22   00 00 00 00 00 00
23..28   <所选网卡 MAC，6 字节>
29       00
30..284  00（255 字节）
```

默认扫描窗口为 1500 ms。扫描完成只是“在窗口内发现了多少有效应答”，不代表该网段不存在其他设备，也不验证 TCP 6600 或串口透传是否可用。

### 5.2 网卡选择约束

可用于扫描的网卡必须同时满足：接口有效、已启用、不是 loopback、具有 IPv4 地址和广播地址，且硬件 MAC 为非全零且首字节最低位为 0 的单播 MAC。多 IPv4 地址的网卡会为每个可用 IPv4 地址生成一个选择项，使广播地址和源地址可明确对应。

## 6. GET 读取配置

读取需要先由搜索取得目标设备的报文头 MAC；仅手工输入 IP 不能构成配置身份。GET 的组帧如下：

```text
00..15   固定协议标识
16       02
17..22   <目标设备的报文头 MAC>
23..28   <所选网卡 MAC>
29       00
30..284  00（255 字节）
```

GET 成功应答必须是 `CMD=82`、长度 `CC`（204）、报文头设备 MAC 合法的 285 字节完整包。虽然已定义配置的主体为前 204 字节，客户端始终保存并在后续 SET 中回送完整 255 字节；最后 51 字节不可因“不认识”而清零。

客户端对 GET 的单次等待时间为 1000 ms，最多发送 3 次 GET。三次都无有效应答时，操作失败，并且在写入流程中保证尚未发出 SET。

### 6.1 数据区布局

已定义配置主体为：`HWCfg[74] + PortCfg[0][65] + PortCfg[1][65] = 204` 字节。本工具使用的设备布局中，端口2配置区从数据区偏移 74 开始，端口1配置区从偏移 139 开始；本工具只编辑列出的端口1字段。

| 字段 | 数据区偏移/长度 | 整包偏移 | 编码与处理规则 |
|---|---:|---:|---|
| 类型、子类型、序号、硬件版本、软件版本 | 0 / 5 | 30 | 只读并原样保留。 |
| 设备名 | 5 / 21 | 35 | 显示时读至首个 NUL；若修改，必须为 1～20 个可打印 ASCII 字符，并清零整个 21 字节区后写入。未修改的非 ASCII 或尾随字节原样保留。 |
| 配置区 MAC | 26 / 6 | 56 | 仅保留，**不是设备身份依据**。 |
| IPv4 地址 | 32 / 4 | 62 | 四个八位组按网络字节顺序。 |
| 网关 | 36 / 4 | 66 | 四个八位组按网络字节顺序。 |
| 子网掩码 | 40 / 4 | 70 | 四个八位组按网络字节顺序。 |
| DHCP | 44 / 1 | 74 | `00` 关闭，`01` 开启。其他值视为无效 GET 应答。 |
| 端口1波特率 | 151 / 4 | 181 | 无符号 32 位**小端**整数。 |
| 端口1数据位 | 155 / 1 | 185 | `05`、`06`、`07`、`08`。 |
| 端口1停止位 | 156 / 1 | 186 | `01` 表示 1 位，`02` 表示 2 位。 |
| 端口1校验位 | 157 / 1 | 187 | `00` 奇、`01` 偶、`02` Mark、`03` Space、`04` 无。 |

示例：115200、8N1 在数据区 151～157 是 `00 C2 01 00 08 01 04`；9600 的波特率字段为 `80 25 00 00`。

### 6.2 报文头 MAC 与配置区 MAC 的区别

设备身份、GET/SET 目标和写后重新发现均使用**报文头偏移 17～22 的 MAC**。实机样本中，报文头 MAC 是 `5C:53:10:21:60:02`，而数据区偏移 26～31 是 `02 03 04 05 06 07`。二者不一致不是本工具拒绝 GET 的理由；配置区 MAC 必须按原始字节保留。

## 7. SET 写入、校验与保留规则

### 7.1 输入校验

写入前客户端在内存中构造候选配置，只有以下检查全部通过才会继续：

| 项目 | 规则 |
|---|---|
| 设备名 | 1～20 个可打印 ASCII 字符（`0x20`～`0x7E`）。 |
| 波特率 | 300～10,000,000 的整数。这个范围是客户端允许值；芯片/时钟模式是否实际支持仍须实机验证，旧模块通常以 921600 为常见上限。 |
| 数据位 | 仅 5、6、7、8。 |
| 停止位 | 仅 1、2。 |
| 校验位 | 仅表 6.1 的 0～4。 |
| 静态网络地址 | IPv4 格式；掩码必须连续且同时保留网络位、主机位；设备 IP 不能是网络地址或广播地址；网关可为 `0.0.0.0`，否则必须是同一子网内的有效主机地址。 |

DHCP 开启时，IP、掩码、网关输入框不参与写入：客户端保留最新读取快照中的三个字段，不把控件里可能遗留的草稿写成零。只修改名称或串口参数时，已有网络字段（即使不满足当前静态地址校验）同样原样保留。

### 7.2 读改写，而非默认值覆盖

SET 绝不根据 UI 默认值拼装。写入使用下列规则：

1. 打开配置窗口先 GET，取得 `baseline` 完整 255 字节快照。
2. 点击写入后再次 GET，取得 `fresh` 快照。
3. 仅比较用户实际编辑的字段。若这些字段在两次 GET 间被外部修改，返回“冲突”，不发送 SET；未编辑字段的外部变化保留在 `fresh` 中。
4. 只覆盖用户编辑的字段，其他 255 字节逐字节保留，生成 SET。
5. 如果候选完整数据与 `fresh` 完全相同，返回“无有效变化”，不发送 SET。

SET 组帧如下：

```text
00..15   固定协议标识
16       01
17..22   <目标设备的报文头 MAC>
23..28   <所选网卡 MAC>
29       CC
30..284  <最新 GET 的完整 255 字节数据，仅替换已编辑字段>
```

SET 最多只发送一次。客户端不会因为丢失 ACK 而重发 SET，也不会额外发送复位命令，避免对设备进行不可控的重复写入。

## 8. 写后重新发现与读回验证

```text
GET baseline → 用户编辑 → GET fresh → 冲突检查 → SET（一次）
                                              │
                                              ├─ 收到 81 ACK：立即搜索
                                              └─ 1 s 未收到 ACK：仍然搜索

搜索同一报文头 MAC → GET → 比较目标字段
   ├─ 一致：已验证
   ├─ 不一致：在 15 s 总窗口内继续 GET / 重新搜索
   └─ 到期：读回不一致，或写入结果未确认
```

写入发出后，客户端以 15 秒总截止时间进行验证。每次 GET 的等待时间仍为 1 秒、最多 3 次；读回失败后回到按同 MAC 搜索，再尝试 GET。这样可容忍设备在写后重新上线、地址变化或 ACK 丢失的情况。DHCP 开启时不要求读回 IP/掩码/网关与写前静态地址相同，但名称、DHCP 状态和端口1串口参数必须符合预期；静态模式还必须比较三项地址。

| 结果 | 含义 | 是否能认为已写入 |
|---|---|---|
| 已验证（Verified） | 读回的目标字段全部一致。 | 可以认为配置存储值已核验；串口实际通信和断电保持仍待实机确认。 |
| 读回不一致（Mismatch） | 在 15 秒内读到设备，但目标字段仍不一致。 | 不可以。 |
| 写入结果未确认（Unconfirmed） | SET 已发出，但未完成重新发现与读回；可能有 ACK，也可能没有。 | 不可以；超时不等于未写入，应重新扫描、读取。 |
| 设备拒绝（Rejected） | 收到 `C1`（SET）或写前读取收到 `C2`（GET）。 | 不可以。 |
| 冲突（Conflict） | 写前二次 GET 发现用户编辑字段已被外部改动。 | 未发送 SET。 |
| 读取错误 / 取消 | 写前 GET 失败、网卡/端口错误，或在发 SET 前取消。 | 未发送 SET。发 SET 后取消按“未确认”处理。 |

协议没有事务序号。因此同一设备、同一命令的迟到 UDP 包无法完全可靠地区分。客户端通过单事务运行、目标 MAC、电脑 MAC、网卡接口、命令状态和写后读回来降低风险，但不能将其宣传为事务级绝对关联。

## 9. 接收过滤与异常处理

为避免其他网卡、其他设备或过期包污染当前事务，客户端会依次过滤：

1. 本地 socket 必须仍绑定，且当前操作尚未结束。
2. UDP 源端口必须是 50000；若系统提供接口索引且当前网卡有索引，二者必须相同。
3. 包必须是 285 字节且带正确协议标识。
4. 报文中的电脑 MAC 必须等于所选网卡 MAC，或为全零（兼容部分设备的回包行为）。
5. 搜索阶段只解析 `84`；写后搜索还要求报文头设备 MAC 等于目标 MAC。读取/写入阶段要求报文头设备 MAC 等于目标 MAC。
6. 只有当前状态允许的命令才会推进状态机；重复包和不相关包被忽略。

如果 UDP 60000 绑定失败、网卡无效、报文发送失败或读取超时，客户端给出明确错误且不崩溃。发出 SET 后若网络故障或用户停止等待，结果必须显示为“写入结果未确认”，不能错误宣称“未写入”。

## 10. 与 TCP 串口透传的边界

扫描、GET、SET 都是 UDP 50000/60000 配置通信；它们与 CH9121 的 TCP 串口透传是两条不同链路。串口测试工具在配置流程中要求 TCP 连接处于断开状态，测试运行中也禁止配置，防止业务数据和设备重配置交叉。完成配置后，仍须单独对 TCP 6600 连接、端口1实际串口收发、目标波特率和断电保持进行验证。

## 12. 维护规则

- 修改字段偏移、命令、过滤规则或时序时，必须同步更新本文件和 `Ch9121ConfigTest.cpp` 的回归样例。
- 新增 CH9121A/T 扩展命令前，先单独确认其固定长度、字段布局和副作用；不得把扩展字段混入本协议的 255 字节读改写流程。
- 若实机发现新的回包形式，应保存脱敏后的完整 285 字节样本，并明确记录它是已验证事实还是待确认推断。
